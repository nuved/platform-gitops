How it works

The homepage says what you get. This page says what actually runs, because the part worth judging is what the platform refuses to do.

Four steps

A different piece of the platform owns each one, and each one leaves something behind you can check.

  1. 1Sign in as yourself

    Identity lives in Authentik, not here. The console sends you there for the ordinary browser sign-in; the nuved CLI (curl -fsSL https://get.nuved.io/install.sh | sh) uses the device flow, where you approve a nine-digit code in a browser. No password ever reaches Nuved, and there is no shared demo login.

    Sign-up is open by invitation only: the enrolment flow is gated behind an invitation stage, so an address nobody invited never reaches the form.

  2. 2Top up, and a tenant appears

    Stripe Checkout takes the payment, in test mode. The signed webhook is what does the work: plans-backend writes the credit to Postgres, which is the source of truth for every cent, and creates a Tenant in the cluster carrying your caps.

    The webhook is idempotent on Stripe's event id, and a delivery whose credit or provisioning fails is answered 500 so Stripe retries it rather than losing the money.

  3. 3A project becomes a namespace

    The tenancy-operator turns each project into a namespace with a ResourceQuota built from the caps you set, a LimitRange so a container that declares no requests still gets some, a default-deny NetworkPolicy, and a RoleBinding to the built-in edit role scoped to that one namespace.

    Change the caps and the quota changes under the running services. Nothing over the quota is admitted, so nothing over it is ever billed.

  4. 4A token reaches one project

    The kubeconfig you download points at kube.nuved.io, the platform's own API proxy, never at the Kubernetes API. The proxy checks the token, works out which project it belongs to, and refuses every request outside it before Kubernetes sees it.

    That is why kubectl get ns with an agent token lists exactly one namespace, and why reading another project's pods comes back Forbidden with a sentence instead of a stack trace.

What reaches what

Four paths, each with exactly one door. Nothing gets to a namespace except through one of these.

This page is one of those Services. It is deployed from apps/www in the public manifests repo by Argo CD, into a namespace with the same quota, the same policies and the same Gateway as a customer's — no exception for being ours.

What the platform enforces

Every line here is a rule the cluster applies on its own, not advice in a runbook. The tag says which component refuses you when you break it.

  • One namespace per project, labelled with its tenant and projecttenancy-operator
  • A ResourceQuota per project built from your caps, and a LimitRange so a container that declares no requests still gets sometenancy-operator
  • A default-deny NetworkPolicy: pods talk to their own namespace and to DNS, nothing elsetenancy-operator
  • A RoleBinding to the built-in edit role, scoped to the one namespacetenancy-operator
  • The operator will not adopt a namespace it did not create, so deleting a project can never take someone else's with ittenancy-operator
  • An agent token reaches exactly one project; every other namespace, and the machines, answer Forbiddenkube.nuved.io
  • The Kubernetes API is never published: every customer request arrives through the proxykube.nuved.io
  • No privileged containers, no host network, host PID or host IPCKyverno admission
  • Non-root only, no privilege escalation, all capabilities dropped, seccomp on, no hostPath, no hostPortKyverno admission
  • No PodDisruptionBudget that blocks every eviction and would stall a node drainKyverno admission
  • An Argo AppProject per platform workspace, locked to that namespace, this repo, and five resource kindsArgo CD
  • kubeconform plus those same Kyverno policies on every pull request, so the answer arrives before the mergeCI gate
  • Your balance is the ceiling: at zero the meter pauses every service and a top-up restores the replica counts it wrote downplans-backend
  • No static AWS keys anywhere in the cluster: service accounts assume roles through the cluster's own OIDC issuerIRSA

What this is, honestly

One machine, one engineer, invitation only

  • One node. The whole platform, this page included, runs on a single small AWS machine managed by kops. There is no high availability: when that node restarts, everything on it goes down with it.
  • Stripe is in test mode. Nothing is charged. Balances, the ledger and the hourly meter are real code doing real arithmetic against a test-mode payment.
  • No undo yet. There is no trash and no nightly snapshot, so deleting something inside a project is final. Give an agent a project you could afford to lose.
  • No build service. You bring a container image. Building one from a folder is the next thing being built, not something that works today.
