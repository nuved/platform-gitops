What your agent can and can't do.

The agent gets a token for one project. Everything below is enforced by the cluster itself, so none of it depends on the agent behaving.

It can

  • Deploy with the kubectl it already knowsYou hand it a kubeconfig for one project. There is no agent-only tool to learn.
  • Read logs, restart and scale, inside the caps
  • Give a service a public addressExpose on the console row, or one API call, and the platform makes the route in seconds. Your first project answers at <service>-<org>.nuved.io, any other at <service>-<org>-<project>.nuved.io.
  • Delete and redeploy what it made, in its own project

It can't

  • Spend past your balanceOnly you can top up. There is no card on file for the agent to reach.
  • Go over the caps you setThe quota refuses it before anything starts, so it never runs and it is never billed.
  • Reach another project, or the machinesBoth answer Forbidden at the door, before the request reaches Kubernetes.
  • Change the caps, the tokens or your account

Each project is its own walled-off space: its own network, its own quota, its own rules about what a container may do. Two projects on the same account can't reach each other.

Not built yet, so you should know: there is no trash and no nightly snapshot, which means a delete inside a project is final today. Give an agent a project you could afford to lose. Both are next, along with building an image straight from a folder.

How it starts.

Three steps, about five minutes. The agent does the rest.

  1. Get in

    The preview is invitation-only while it runs on one machine. Ask for an invitation, then sign in with your own account — the same one, every time, no shared password.

  2. Top up

    €10 or more by card. That balance is the most this account can ever spend. When it reaches zero every service pauses and nothing is deleted.

  3. Hand your agent the keys

    Make a project, set the most vCPU, memory and services it may use, and create a token for that one project. Download its kubeconfig and point the agent at it.

    # AGENTS.md
Deploy with: KUBECONFIG=~/.kube/shop-agent kubectl apply -f k8s/
Project shop is capped at 0.5 vCPU and 1 GiB. Set small,
explicit requests — anything larger the server refuses.

Questions.

What is a project?

A walled-off space for one app: its services, its caps, its agent token and its own network. Other projects can't reach it, and it can't reach them.

Which agents work?

Any agent that can run a shell command — Claude Code, Codex, Cursor, Aider. They use stock kubectl with the kubeconfig you give them, so there is nothing new for the agent to learn. It works from your own terminal too.

Do I need your CLI?

Only you do. nuved signs you in and manages projects, tokens and your balance; your agent needs nothing but kubectl. Install it with curl -fsSL https://get.nuved.io/install.sh | sh, or do the same things in the console.

Where does my code live?

Wherever it lives now, GitHub or your laptop. You bring a container image and the agent applies it into your project. Building the image here, straight from a folder, is the next thing we ship.

What happens when the balance hits zero?

Every service pauses and nothing is deleted. Top up and they come back with the replicas they had.

Can the agent delete my data?

Inside its own project, yes — and today that is final, because the trash and the nightly snapshot aren't built yet. It cannot reach another project, your caps or your balance.

Is this real?

A preview on one machine, run by one engineer, open by invitation. Payments go through Stripe's test mode, so nothing is charged. The caps and the isolation are real: they are the cluster's own quotas and network rules, not a check in our code.
